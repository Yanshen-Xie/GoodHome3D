# 代码说明

本文按模块说明系统的实现原理和关键代码位置，便于阅读、修改和答辩讲解。行文顺序与程序运行顺序一致：先搭场景，再加人物，最后是各功能页。

## 1. 程序入口与主循环（src/main.js）

启动时依次完成：

1. 创建 WebGL 渲染器，开启软阴影（`PCFSoftShadowMap`）、材质级裁剪（`localClippingEnabled`，用于剖切）和 ACES 色调映射。
2. 创建导航网格、室外环境、房屋、家具、设备，加载人物。
3. 创建六个功能页对象，生成界面。
4. 预编译着色器，进入主循环。

主循环 `loop()` 每帧执行：推进模拟时钟 → 更新门窗和窗帘动画 → 更新人物 → 更新摄像机 → 调用各功能页的 `update(dt)` → 渲染场景和 HTML 标签。每 0.5 秒再调用一次 `slowUpdate`，用于环境模拟、图表刷新等不需要每帧计算的工作。

所有模块共享一个 `app` 对象（场景、摄像机、房屋、设备、人物等都挂在上面），各功能页通过它互相联动。

## 2. 户型与房屋（src/scene/layout.js、house.js）

户型用数据描述：`ROOMS` 是两层共 17 个空间的矩形范围（带楼层号），`WALLS` 是每层墙体中心线和墙上的门窗洞口，`STAIR`、`ELEVATOR` 是楼梯和电梯的位置。改户型只需要改数据。

地面用 `ShapeGeometry` 生成，二层楼梯厅在楼梯洞口和电梯井处挖洞；楼板用 `ExtrudeGeometry`（带洞的形状挤出）生成。坡屋顶由两块倾斜 25° 的屋面板、屋脊、两侧三角形山墙组成；檐沟和四角落水管把雨水引到地面。

U 形楼梯：第一跑是实心踏步（每级一个长方体，高度逐级增加），第二跑是悬挑踏步板加斜梁，中间是休息平台；二层洞口设玻璃护栏。`stairHeight(x, z)` 返回楼梯上任意一点的踏面高度，漫游和人物走楼梯都用它。

细节构件：每段墙体底部朝室内的一侧贴踢脚线，一层外墙底部贴花岗岩勒脚，外墙门窗四周加白色窗套和窗台，一、二层之间有腰线。

墙体生成（`buildHouse` 中的 `add`）：沿墙方向，把墙切成“洞口之间的整段墙”“窗下墙”“洞口上方过梁”三类长方体。每块墙体的 6 个面分别判断朝向哪个房间（向外偏移 0.15m 取样，`sideMaterial`），外侧用石材、厨卫用瓷砖、其余用乳胶漆。

纹理不拉伸：`projectUV` 按世界坐标给每个面设置 UV（朝 z 的面用 x、y，朝 x 的面用 z、y，朝上的面用 x、z），再除以贴图代表的真实尺寸。这样同一面墙被门窗切成几块后，纹理仍然连续。

门窗：窗户由窗框、固定扇和可滑动扇组成，开窗时滑动扇平移；门扇挂在铰链一侧的父节点上，开门就是绕 y 轴旋转父节点。

## 3. 程序化纹理与材质（src/scene/textures.js、common.js）

每种纹理用 Canvas 2D 绘制，例如木地板是错缝排列的长条，每块颜色随机浮动并加几条贝塞尔曲线当木纹；最后整体叠加细小噪点。每张纹理记录它代表的真实边长（`worldSize`），配合上面的 UV 计算保证比例一致。

法线贴图（`normalFromTexture`）：把颜色贴图的亮度当作高度，用 Sobel 算子求出水平、竖直方向的坡度 dh/dx、dh/dy，法线 = normalize(−dh/dx·k, −dh/dy·k, 1)，再编码成 RGB。这样砖缝、瓦片、木板缝在光照下会有凹凸感，而不需要增加几何面数。

`mat(name)` 是材质库，同名材质只创建一次；带 `section` 标记的建筑材质会挂上剖切平面。

## 4. OBJ / MTL 模型解析（src/loaders/objLoader.js）

OBJ 是文本格式，逐行解析：

- `v` / `vt` / `vn`：顶点、纹理坐标、法线，分别存入数组；
- `f`：一个多边形面，每个角是“顶点号/纹理号/法线号”，按扇形拆成三角形 (v0,v1,v2)、(v0,v2,v3)…；
- `usemtl`：之后的面属于哪个材质，每个材质生成一个 Mesh。

MTL 解析出漫反射颜色 `Kd`、高光指数 `Ns`、透明度 `d`、贴图 `map_Kd`。转成 PBR 材质时，用 `roughness = sqrt(2/(Ns+2))` 把 Phong 高光指数换算成粗糙度。

餐椅、马桶、花盆三个模型由 `tools/make-obj.mjs` 生成：长方体直接写 6 个面；马桶、花盆用“车削”（把轮廓线绕 y 轴旋转一周）生成，法线由轮廓切线求出。

## 5. 光照、天空与环境（src/scene/environment.js）

太阳位置 `sunDirection(hour, day)` 使用简化天文公式（广州纬度 23.1°）：

- 赤纬角 δ = 23.44°·sin(360°·(284+n)/365)
- 时角 ω = 15°·(t−12)
- 高度角 sin h = sinφ·sinδ + cosφ·cosδ·cosω
- 方位角 A = atan2(sinω, cosω·sinφ − tanδ·cosφ)

得到的方向同时用于：主光源（平行光 + 阴影）位置、天空着色器的太阳位置、光伏发电计算、日照分析。

光照组成：太阳平行光（主光）+ 半球光（天空色和地面反射色，作为环境光）+ 由天空生成的环境贴图（PMREM，用于玻璃和金属反射）+ 室内每个房间一盏点光源。

天空盒使用 Three.js 的大气散射天空（Sky），并在着色器编译前插入一个亮度系数（`dimSky`），避免色调映射后发白。

## 6. 导航网格与 A* 寻路（src/systems/nav.js）

两层住宅每层一张导航网格（`NavWorld`）。跨楼层寻路时把路线拼成三段：本层起点 → 楼梯口（本层 A*）→ 楼梯上的三维路点（带高度）→ 另一层楼梯口 → 终点（另一层 A*）。人物沿这些带高度的路点移动，就能自然地上下楼梯。


把地面划分成 0.2m × 0.2m 的格子，墙和大件家具所在的格子标记为障碍，再向外扩一格（人有宽度）。

`findPath` 是标准 A*：g 为已走距离，h 为到终点的直线距离，每次从小根堆中取 f = g + h 最小的格子展开；8 邻域移动，斜向代价 √2，斜穿墙角时要求两侧直行格子都可通行。找到路径后做“视线平滑”：能直线走到的点之间去掉中间拐点。

用途：人物日常走动、火灾疏散（`avoidDanger` 时火源周围 1.8m 视为障碍）、无障碍检查（`passWidth` 沿垂直方向测量通道宽度）、漫游碰撞。

## 7. 人物与动画重定向（src/characters/）

真人角色 Michelle 只自带跳舞动画，行走、跑步、站立动画来自另一个骨骼结构相同、但初始姿态和尺寸不同的角色。直接套用会姿态错乱，所以实现了动画重定向（`retarget.js`）：

1. 两个角色都摆成 T-Pose，记录每根骨骼的世界旋转；
2. 对源角色第 t 帧，计算每根骨骼相对 T-Pose 的世界旋转变化量 Δ = Q源(t)·Q源(T)⁻¹；
3. 把 Δ 加到目标骨骼上：Q目标(t) = Δ·Q目标(T)，再换算成相对父骨骼的局部旋转；
4. 按父→子顺序算完所有骨骼，生成新的动画片段。两个模型朝向相差 180°，用一个绕 y 轴的旋转修正。

`people.js` 中两位居民（妈妈、女儿）按作息表随机选择下一个活动地点，用 A* 规划路线，沿路线移动时播放行走动画并平滑转身，到达后切换为站立。女儿的裤子颜色通过修改贴图像素的色相区分（`recolorTexture`，只改黄色区域，皮肤不变）。

另外还有一位"入侵者"（衣服颜色改为深色），只在入侵检测演示时出现；奶奶可以做跌倒动画：人物模型挂在一个父节点下，跌倒时绕脚部旋转约 90°，并冻结骨骼动画。

## 8. 选择与信息卡片（src/systems/selection.js）

鼠标按下和抬起位置相差很小才算“点击”（否则是拖动旋转）。点击时从摄像机向鼠标方向发射射线（`Raycaster`），取第一个可见、未被剖切掉的物体，再沿父节点向上找到带 `userData.info` 的对象，显示其名称、类别、状态、功能、维护信息、实时数据和控制项。

## 9. 各功能页

### 安全耐久（features/safety.js）

- 跌倒检测：奶奶倒地后，毫米波雷达（房间人体存在传感器）检测到"倒地且 3 秒无起身动作"判定跌倒，房间高亮、报警，离得最近的家属（按 A* 路线长度比较，可能要从二楼下楼）跑来扶起。
- 入侵检测：陌生人沿预设路线翻越围栏（经过围栏时身体抬高），依次触发围栏红外对射预警、摄像头识别（红色识别框 + 视野锥变红）、投光灯与声光报警；受威慑后逃离，报警解除。

- 粒子系统（`systems/particles.js`）：每个粒子有位置、速度、寿命，大小和颜色随寿命插值；自定义着色器画圆形柔边点精灵。火焰用加法混合（越叠越亮），烟雾碰到天花板后沿水平方向扩散，并受厨房墙体和防火门约束。
- 处置流程按时间推进（`fireTimeline`）：1.5s 烟感报警 → 2.2s 关燃气、开门解锁、应急照明 → 3s 规划疏散路线 → 厨房无人后关闭防火门。
- 疏散：对每位居民分别计算到三个安全出口的 A* 路线，选最短的；路线用地面流动箭头显示（`systems/pathViz.js`：沿路线生成带状网格，滚动箭头纹理）。
- 一键呼叫：按钮闪烁、房间地面红色高亮、通知日志，家属沿路线跑去救助并统计响应时间。

### 健康舒适（features/comfort.js）

- 日照时长分析：每个房间取 3×3 个采样点，从 5 点到 19 点每半小时朝太阳方向发射射线，未被墙体、屋顶、遮阳板挡住就计为直射，统计小时数。
- 通风：南、东侧开窗为进风口，北、西侧为出风口，用 A* 求进风口到出风口的室内路线作为气流路径，粒子沿路径流动；新风从天花板风口向下扩散。
- 室内环境模拟（`systems/envModel.js`）：温度、湿度、PM2.5、CO₂ 都用一阶惯性模型 x ← x + (目标 − x)(1 − e^(−dt/τ)) 逼近目标值；目标值由室外天气、日照、门窗、空调、新风、人员决定。
- 热力图（`systems/heatmap.js`）：在地面上方叠加一张 Canvas 贴图，每个房间单独裁剪绘制（数值不穿墙），空调、窗户、灶台等位置画径向渐变表示局部差异；颜色按 蓝→青→绿→黄→红 线性插值。
- 无障碍检查：规划轮椅路线，每 0.1m 测一次通道宽度并着色（绿 / 黄 / 红），再在房间内搜索直径 1.5m 的回转空间；轮椅模型沿路线移动。

### 绿色低碳（features/green.js）

- 雨水回用：集水量 = 屋面面积 × 降雨强度 × 径流系数 0.8；蓄水池水位按"进水 − 用水"随模拟时间积分，水体圆柱的高度跟着缩放。剖切显示时把地面上的草皮盖板隐藏，露出地下土坑、切掉四分之一的池壁和水面。喷灌水滴是受重力影响的粒子（每帧 vy −= 9.8·dt）。

- 光伏功率 = 装机容量 × (入射角余弦 × 大气衰减 × 天气系数 + 散射) × 系统效率；光伏板法线为朝南倾斜 20° 的向量，与太阳方向点乘得到入射角余弦。
- 能量分配：光伏先供家用，多余给电池充电，再多余上网；不足时先用电池，再从电网买电。电池电量按模拟时间积分。
- 能量流动：沿折线生成管道（TubeGeometry），贴上渐变条纹并让纹理滚动；滚动方向表示能量方向，速度和透明度随功率变化。
- 家庭用电由设备实际状态累加（灯、空调、新风、电视、热泵），与智慧页的场景模式联动。

### 智慧便捷（features/smart.js）

- 水浸联动：地面积水用一个逐渐变大的圆形水面表示，2 秒后水浸传感器报警，随后关闭进水总阀。
- 下雨自动关窗：天气变为雨天且有外窗开着时，自动关窗并记录日志。
- 夜间窗户透光：外墙每扇窗外侧有一块只朝外的发光面，房间开灯且天黑时变亮，颜色跟随灯的色温。

- 场景模式：一次性设置多个设备的状态（灯的亮度和色温、窗帘、空调、电视、门锁等）。色温转 RGB 使用常用近似公式（`devices.js` 中的 `kelvinToColor`）。
- 人体感应：每 0.5 秒检查每个房间里有没有人，有人且光线不足时开灯，离开 3 秒后关灯；走廊只点亮人附近的那一盏灯，形成“灯随人走”。
- 燃气泄漏联动：浓度随时间上升，达到 10%LEL 预警、20%LEL 报警，随后依次关阀、开窗、开新风，浓度降到 0 后解除。
- 数字孪生运维：把建筑和家具材质临时改为半透明，设备上方显示按状态着色的标记（`systems/statusPins.js`）；模拟故障时设备变红、镜头自动飞过去并显示故障信息，“派单维修”后恢复。

### 分层查看（features/layers.js）

- 楼层显示：只看一层时剖切平面放在一层天花板下（2.95m），看二层时切掉屋顶（6.05m）；每层一张热力图，热力图材质也受剖切平面裁剪，上层的热力图、标签、人物会跟着隐藏。

- 剖切：所有建筑材质共享一个裁剪平面 y < h，拖动滑块修改 h；材质设为双面，切开后能看到墙体内侧。隐藏屋顶时自动切在 2.8m，把天花板上的灯具一起隐去。
- 活动热力图：按一家人一天的作息（地点、停留时长）在密度场上累加高斯“印章”，睡眠权重较低；相邻地点之间沿 A* 路线累加走动；再实时叠加两位居民的位置。最后统计各房间占比，给出布局建议。

## 10. 性能

- 静态几何合并（`systems/optimize.js`）：一件家具通常由十几个长方体、圆柱组成，每个都是一次绘制调用。启动时把"同一件物体里使用同一种材质"的网格合并成一个（`mergeGeometries`），会运动的部件（门扇、窗扇、窗帘、电梯门等，标记为 `dynamic`）不合并。绘制调用从约 3200 次降到约 1400 次，帧率从约 45 提高到 60。每件物体仍是独立对象，点击选择不受影响。
- 灯光池（`systems/lightPool.js`）：全屋有 17 盏灯和若干报警灯、火光、投光灯，如果都用真实点光源，每个像素都要计算所有光源。系统只创建 10 盏真实点光源，每帧从"正在亮"的灯中挑离摄像机最近的 10 盏（报警、火光优先），把位置、颜色、亮度复制给真实光源；光源数量不变，着色器也不用重新编译。
- 栅栏竖条、路面标线、花朵、草丛等大量重复物体用实例化渲染（`InstancedMesh`），一次绘制调用画出全部。
- 环境模拟、图表、热力图每 0.5 秒更新一次，不每帧计算。
- “高画质”开关可降低阴影贴图和渲染分辨率。

## 11. 数据大屏（src/ui/dashboard.js）

深色图表面板覆盖在三维场景两侧：雷达图（安全、舒适、健康、绿色、智慧、适老六项指数，由实时状态计算）、三个仪表盘（光伏、用电、储能）、用电分项饼图、各房间温度柱状图、能源趋势折线图、设备状态环形图、告警事件列表，顶部是关键指标卡片。数据每 0.5 秒刷新。

## 12. 测试脚本（tools/）

- `tour.mjs`：自动依次执行 34 个演示步骤（各功能页、各场景、漫游上楼），截图并记录帧率和报错。
- `interact.mjs`：用真实鼠标键盘操作测试 15 项：点选物体、信息卡片控制、楼层切换、电梯呼叫、场景模式、设备列表、数据大屏、时间滑块、漫游移动与碰撞、漫游走楼梯上二楼、人物跨楼层寻路等。

运行方法：先 `npm run dev` 启动开发服务器，再 `node tools/tour.mjs` 或 `node tools/interact.mjs`（需要先 `npx playwright install chromium`）。
