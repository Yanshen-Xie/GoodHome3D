# “好房子”三维可视化系统

计算机图形学课程大作业二。基于 WebGL（Three.js）实现的两层住宅三维可视化系统，围绕“安全、舒适、绿色、智慧”四类特征，展示住宅的建筑、家具、设备、人员活动和运行数据。

## 一、运行方法

### 1. 直接运行（推荐，用于演示）

用 Chrome 或 Edge 浏览器打开 `release/好房子三维可视化系统.html`（双击即可）。

这个文件已经包含全部代码、模型和贴图，不需要联网，也不需要安装任何软件。首次打开需要几秒钟加载。详细操作见 `release/操作说明.pdf`。

### 2. 从源代码编译

需要 Node.js 18 或更高版本。

```bash
npm install          # 安装依赖（three、echarts、vite）
npm run typecheck    # 检查 TypeScript 模块
npm run dev          # 开发模式，浏览器打开 http://127.0.0.1:5188/
npm run build        # 编译，生成 dist/index.html（单个文件）
bash scripts/package.sh   # 类型检查、编译并复制到 release/，生成操作说明 PDF，同时打包源代码
```

`scripts/package.sh` 用 Typst 把 `docs/操作说明.typ` 编译成 `release/操作说明.pdf`。Typst 不在 PATH 中时，用环境变量指定路径，例如 `TYPST=/path/to/typst bash scripts/package.sh`；找不到 Typst 时跳过 PDF，其余步骤照常完成。

## 二、界面与操作

| 区域 | 说明 |
|---|---|
| 顶部标签页 | 总览、安全耐久、健康舒适、绿色低碳、智慧便捷、分层查看 |
| 右上角 | 楼层切换（整栋 / 一层 / 二层）、数据大屏、帧率 |
| 左侧面板 | 当前功能页的按钮、开关、数据卡片和图表 |
| 右侧信息卡片 | 点击场景中的物体后显示名称、功能、状态、维护信息，设备可直接控制 |
| 左下角 | 11 个预设视点和第一人称漫游 |
| 底部时间栏 | 时间、播放速度、日期（夏至 / 春分 / 秋分 / 冬至）、天气（晴 / 多云 / 雨） |

家具、整屋设备和外部模型共用独立模块的创建与生命周期接口；户型装配负责摆放，单件工厂负责几何、行为和能力。场景模块由模块宿主（`src/modules/host.ts`）统一挂载、移动和释放，导航占地随之更新；门窗通过 `openings` 服务按编号查询和控制；六个功能页只依赖 `src/features/services.ts` 中各自需要的那部分服务，不再直接读写整个应用对象。拆分进度及剩余项见 [TODO.md](TODO.md)。

### 独立模块预览（开发工具）

运行 `npm run dev` 后，整屋主界面右上角会出现“原子模块预览”入口；也可直接访问 <http://127.0.0.1:5188/src/dev/module-preview.html>。预览页与整屋应用通过同一个 `ModuleCatalog` 注册函数创建家具、设备样例和整屋实际使用的设备工厂，可查看模块信息与能力、操作设备控件、调整位置和比例、播放 GLB 动画，也可加载本地 GLB 或 URL GLB/GLTF（加载新模型时会取消上一次尚未完成的加载，内容不是 GLB/GLTF 时给出明确提示）。`device-*` 是方便比较的简化样件，`house-*` 是整屋使用的实际模块工厂。

从整屋主界面的入口打开预览页时，“整屋实时模块”面板会通过 `window.opener` 连接主界面，可直接查看和操作整屋中正在运行的家具和设备，调整位置（导航占地同步更新）或在整屋中定位。直接输入地址打开、或主界面已关闭时，该面板不可用。

该页面供开发调试使用，不会并入面向演示的单文件 `dist/index.html`。

鼠标：左键拖动旋转，右键拖动平移，滚轮缩放，单击选择物体，双击将镜头对准物体。

漫游：W/A/S/D 或方向键移动，鼠标拖动转向，Q/E 转身，Shift 加速，Esc 退出。会被墙和家具挡住，走到楼梯可以上下楼。

## 三、功能与评分要求对照

### 基础要求

| 检查项 | 实现情况 |
|---|---|
| 场景范围 | 两层住宅主体（地基与勒脚、墙体、门窗与窗套、楼板、U 形楼梯、家用电梯、南阳台、坡屋顶、檐沟落水管、雨棚）；16 个室内空间的家具布置；室外庭院、车道与汽车、道路、人行道、围栏、乔木与草丛、花坛、露台、路灯、邻居住宅、远山 |
| 模型构成 | 建筑构件、家具、家电、智能设备、消防设施、能源设备、车辆、人物、植物等十余类独立物体；墙体按门窗洞口自动切分，无重叠闪烁 |
| 尺度与空间关系 | 真实米制尺寸：层高 3.2m、门宽 0.9~1.0m、踏步高 0.18m、栏杆高 1.1m、人物身高约 1.66m |
| 摄像机与视角 | 轨道旋转 / 缩放 / 平移；11 个预设视点平滑飞行；楼层切换；第一人称漫游（碰撞、上下楼梯）；双击聚焦 |
| 基础交互 | 射线拾取选择物体（被剖切的部分不可选）；信息卡片开关、调节设备；时间、日期、天气、剖切高度、图层等参数控制 |
| 材质与纹理 | 20 种程序化纹理（木地板、瓷砖、石材、涂料、花岗岩、屋面瓦、木饰面、光伏板等），按真实尺寸计算 UV；由纹理自动生成法线贴图，表面有凹凸质感 |
| 光照与阴影 | 太阳平行光（主光，按经纬度与时间计算方向）+ 半球光（环境光）+ 天空环境贴图；室内灯光池（固定 10 盏点光源动态分配给最近的亮灯）；PCF 软阴影；夜间窗户透光 |
| 环境表现 | 大气散射天空盒（随太阳位置变化）、草地与草丛、道路、远山、雾效、雨天粒子 |
| 视觉一致性 | 统一 PBR 材质与 ACES 色调映射 |
| 实时性能与稳定性 | 34 个演示步骤中 31 步 60 FPS，最低 51 FPS（测试环境与条件见第五节）；静态几何按材质合并（总览视角每帧绘制调用由约 4800 次降到约 1900 次）；实例化渲染；主循环中各项任务单独做异常保护；可切换画质；整个应用可完整销毁和重建 |
| 工程规范 | 单文件即可运行；源代码可重新编译，TypeScript 严格模式类型检查通过；附自动演示、交互测试、几何检查和疏散检查脚本 |

## 五、测试与验收结果

以下结果均可用 `tools/` 中的脚本复现：先 `npm run dev` 启动开发服务器，执行一次 `npx playwright install chromium`，再运行 `node tools/<脚本> http://127.0.0.1:5188/`（`tour.mjs` 还需要第二个参数指定截图目录）。

测试环境：Linux 服务器，NVIDIA RTX 5880 Ada（驱动 570），Intel Xeon Platinum 8473C；Playwright 1.48 自带的无头 Chromium，Vulkan 后端，窗口 1600×900，高画质开启。测试时服务器上同时运行着其他 GPU 任务。

| 检查 | 脚本 | 结果 |
|---|---|---|
| 自动演示 | `tour.mjs` | 34 个步骤全部执行，页面报错 0 个；31 步 60 FPS，其余为 59、58、51 FPS（51 FPS 出现在数字孪生透明化视图） |
| 交互测试 | `interact.mjs` | 15 项全部通过 |
| 乱点测试 | `monkey.mjs` | 六个功能页的全部按钮和开关点击两轮（第二轮打乱顺序），共 237 次，报错 0 个；每页点完后测帧率，第一轮点完智慧便捷页（含数字孪生透明化等效果同时开启）时最低 38 FPS，其余 11 次为 56~60 FPS |
| 穿插检查 | `overlap_check.mjs` | 无真实穿插；脚本列出的电视、燃气管两处经截图确认为包围盒重叠（物体贴靠，实际不相交） |
| 悬空检查 | `float_check.mjs` | 疑似悬空 0 件 |
| 地点检查 | `points_check.mjs` | 居民作息地点、救助目标点、电梯门前共 25 处，全部可站立、可到达 |
| 疏散检查 | `evac_check.mjs` | 厨房起火时，两层所有可站立位置均能绕开火源到达安全出口 |
| 长时间运行 | `soak.mjs` | 时间快速播放、人物自由走动 4 分钟（模拟约 3 天），检查 24 次：平均 59 FPS、最低 55 FPS，报错 0 个，卡住、穿墙、悬空 0 次，内存稳定在 77MB |
| 软件渲染 | `swiftshader.mjs` | 关闭 GPU、用 SwiftShader 渲染：加载约 10 秒，报错 0 个，帧率 60 |

说明：

- 帧率按浏览器 `requestAnimationFrame` 每秒实际帧数统计，受显示刷新率限制，60 FPS 即为上限，不代表渲染能力的极限。
- 软件渲染测试在 208 核的服务器 CPU 上进行，只说明没有独立显卡时也能正常显示、不报错；普通笔记本的 CPU 核数少得多，帧率会明显更低，此时可关闭“高画质”。
- 绘制调用数为总览视角下一帧的统计（含阴影绘制）；地址后加 `?nomerge` 可关闭静态几何合并进行对比。

## 六、素材来源

- 人物模型 `Michelle.glb` 与动画来源 `Soldier.glb` 来自 Three.js 官方示例（原始角色与动画出自 Adobe Mixamo）。系统中只显示 Michelle，`Soldier.glb` 仅用于提供行走、跑步、站立动画。
- 餐椅、马桶、花盆的 OBJ 模型由 `tools/make-obj.mjs` 生成。
- 所有纹理由代码绘制（`src/scene/textures.ts`），未使用外部图片。
- 第三方库：Three.js（MIT）、ECharts（Apache-2.0）、Vite（MIT）。

## 七、说明

- 室内环境、光伏发电、能耗、碳排放、雨水量等数据为按简化模型计算的模拟值，用于展示可视化效果，不代表真实测量结果。主要假设：
  - 太阳位置按广州纬度 23.1° 的简化天文公式计算，不考虑大气折射和地形。
  - 室内温度、湿度、PM2.5、CO₂ 用一阶惯性模型逼近目标值，目标值由室外天气、日照、门窗、空调、新风和人员按经验系数决定，不做流体或传热计算。
  - 光伏功率按装机容量、入射角余弦、大气衰减、天气系数和系统效率估算；用电量由各设备的开关状态和设定功率累加；碳排放按全国电网平均排放因子 0.5703 kgCO₂/kWh、电费按 0.62 元/kWh 折算。
  - 雨水集水量 = 屋面面积 × 降雨强度 × 径流系数 0.8；火灾烟雾、燃气浓度、水浸按固定时间线推进，仅用于演示联动流程。
  - 这些结果适合对比不同方案的趋势（如有无遮阳、普通方案与绿色方案），不能用于工程设计或节能评估。
- 系统在 Chrome / Edge 最新版中测试通过。
